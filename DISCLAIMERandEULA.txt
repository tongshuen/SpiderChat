7.1 Chat History Encryption Vault (Optional)
This Software provides an optional "Chat History Encryption Vault". When enabled, the plaintext of messages in the local chat history database (SQLite) is stored encrypted with AES-256-GCM on a per-message basis; each message uses an independent key derived from its message ID, and search decrypts messages piecewise (one by one) to avoid loading and decrypting the entire database into memory at once. The vault's master key is derived from your vault PIN via PBKDF2-HMAC-SHA256, with a randomly generated salt stored alongside the database. The developer does not hold your master key or vault PIN; if you forget the vault PIN, encrypted chat records will be unrecoverable, and the developer assumes no liability for any resulting data loss.

7.2 Ephemeral / Burn-on-Read (Optional)
This Software provides an optional "Ephemeral / Burn-on-Read" feature. It supports automatically deleting read messages by three kinds of rules — globally, by a specified list of contact UUIDs, or by message text matching a specified regular expression — and offers two deletion modes: "fast delete" (direct deletion) and "secure delete" (overwrite with random data before deletion, including associated attachments). Ephemeral deletion is triggered after a read receipt is sent/received for a matching message. Because message bubbles are already rendered in memory, they will not disappear from the screen immediately, but will be gone the next time the chat window is reopened and reloaded. Secure delete is subject to the characteristics of SQLite file layout and storage media (e.g., SSD wear leveling), and cannot guarantee physical irrecoverability; for sensitive scenarios, please combine with full-disk encryption on your device.
